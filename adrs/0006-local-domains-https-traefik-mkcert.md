# 6. Local domains and HTTPS with Traefik and mkcert

- Status: Accepted; how the front reaches the API superseded by ADR-0012
- Date: 2026-10-03

## Context

Local development should use real domain names and HTTPS, so behaviour that depends on origins (CORS, secure cookies, redirects) matches production.

## Decision

- The apps are served at:
  - `https://emploi.localhost` → `front`
  - `https://api.emploi.localhost` → `back`
- **Traefik**, the ingress controller k3s ships by default, routes traffic. The k3d load balancer maps host ports 80 and 443 to it, on IPv4 and IPv6 (`*.localhost` resolves to `::1` on the dev machine).
- TLS certificates are generated by **mkcert**, whose local CA is trusted by the browser. One certificate covers `emploi.localhost` and `*.emploi.localhost` and is stored as a Kubernetes TLS Secret. Certificate files are not committed.
- HTTP redirects to HTTPS.
- Origins (API URL, CORS allowlist) come from environment variables, not hardcoded strings.

## Consequences

- No `/etc/hosts` edits are needed.
- mkcert must be installed and its CA trusted on each dev machine.
- Host ports 80 and 443 must be free while the cluster runs.
